产品定位

Nexus 是智能体的运行时。

模型负责推理与决策，Nexus 负责上下文、工具、权限与事件记录。任务在执行前完成规划与确认，执行中可审计、可回放，必要时可依据检查点恢复。

运行流程

单次执行按固定顺序推进，每一步都写入事件流。

  1. 上下文

    组装上下文

    按预算装配系统提示、工具与历史；超出预算时压缩，长输出落盘、按需读回。

  2. 模型

    调用模型

    流式返回思考与正文，并给出将要调用的工具。

  3. 工具

    执行与审批

    只读操作并行，写入与命令执行先行审批；提交前展示路径、命令与改动对比。

  4. 检查点

    写入留快照

    写入工作区前创建逐文件检查点，保留改动前的版本。

  5. 收尾

    验证与汇总

    运行验证命令，汇总变更、用量与费用；失败可依据检查点恢复。

写前审批，全程留痕

会修改工作区或产生费用的操作，均先展示、后执行；未获确认不执行。

  • 写前改动对比展示路径、工作目录，以及改动前后的内容。
  • 逐文件检查点写入前保留快照，可对照改动前的版本。
  • 可回放的事件流事件仅追加，配合本地数据库投影，重启后可恢复现场。
  • 用量与费用每次调用记录用量、缓存读写与费用，并按会话汇总。

扩展能力

核心与领域无关，能力以扩展方式接入：工具提供动作，技能提供方法，插件与外部工具负责集成。

工具

文件读写、检索、命令执行、网络访问、图像生成、Office 与终端。

技能

声明式任务包，按需检索与读取，为特定任务提供方法与约束。

插件

通过贡献点扩展界面、命令、事件与设置；内置皮肤与启动动画。

外部工具（MCP）

通过 MCP 接入的外部工具，沿用同一套审批与事件记录。

子代理

只读与全量两类子代理，各自独立的上下文，结论回传主会话。

多家模型服务

兼容 OpenAI 接口与 Anthropic，支持缓存有效期与思考回传。
