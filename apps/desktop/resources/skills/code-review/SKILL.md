# Code Review

## 目标

找出影响正确性、安全性、数据、兼容性或可维护性的问题，按严重程度给出可执行结论。

## 步骤

1. 确认 review 范围：文件、目录、diff 或具体方案；范围不清时先询问。
2. 阅读相关入口、调用方、类型契约和测试，不只孤立看改动片段。
3. 检查逻辑错误、边界条件、异常路径、资源释放和状态机。
4. 检查权限、路径穿越、命令注入、密钥泄露和不可信输入。
5. 检查并发、事件顺序、持久化一致性和错误重试。
6. 区分确定的问题和待确认风险，没有证据不要断言。

## 输出

- 先列阻断性问题，再列建议。
- 每条包含文件路径、行号、影响和修复方向。
- 给出必要验证或缺失测试；用户未要求时不直接改代码。
